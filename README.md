# CINEMAX

CINEMAX is an early-stage, Arabic-first iPhone streaming client built with Kotlin Multiplatform and Compose Multiplatform. The Android target has been removed: the app targets iOS only.

## Implemented in the current repository
- Two exported source lists ship in the app bundle (`iosApp/Sources/raif-sources.json` and `raif2-sources.json`) and are merged at launch into one list with a single entry per manifest URL, so the repeated addons that appear in both files are dropped before anything is shown. The merged list is offered for one-tap install inside "إضافة مصدر" with its own search field; an addon that is already installed reads "مثبّت", the row that is installing reads "جارٍ…", and an entry the app cannot load (a plain `http://` address, say) is filtered out instead of failing later. The parsing, URL normalisation and de-duplication live in `core/SuggestedSources.kt` with tests.
- The player lists its own sources: "المصادر" in the top bar opens the ranked direct links and switching one restarts playback in place, with the playing link marked "يعمل الآن", so a bad source no longer means leaving the player and going back to the detail screen.
- A source that dies before it starts playing is skipped automatically: the player moves to the next ranked direct link (three attempts at most, never repeating a link) and says which one it is trying, instead of leaving a black screen with a red line. When no link is left it says so and points at the in-player source list.
- The player lists the audio tracks packed inside the file (a dual-audio MKV, say) behind "الصوت" in the top bar, names them by language, title and format, marks the track playing, and switches to the chosen one immediately without restarting playback. A null choice never turns audio off, so the player's own default track is kept.
- Duplicate sources are merged by file identity, not by addon: a torrent by its info hash plus the file inside a season pack, a direct link by its URL with tracking, signature and expiry parameters removed, so one film offered by several addons (Stremio, Nuvio and the built-in archive together) appears once, under its best-described entry, with "متوفر في: A · B" naming every provider. Lives in `core/SourceFingerprint.kt` with tests.
- Each link keeps a small track record — last success, last failure, time to first frame — so a source that just failed drops below the working ones and fades back over three days, a link that played before rises, and the last-played link stays pinned on top. Stored per fingerprint in `SourceStatsStore`; the ordering is `rankSources` with tests.
- The source sheet says what it is offering: the main button names the quality that will play ("▶ مشاهدة • 1080p"), a line under the filters counts the sources and the addons that answered, the in-player source list names every provider instead of one addon, and Settings can hide links that failed in the last day ("إخفاء المصادر المعطلة") or forget the health history ("مسح سجل جودة المصادر").
- A source can be pinned per title ("☆ اجعله المصدر المفضل"): the detail screen and the player try it first regardless of ranking, mark it "مفضل", and the choice survives launches (`PreferredSourceStore`, with tests).
- "الجودة المفضلة عند التشغيل" in Settings (تلقائي / 4K / 1080p / 720p) decides what the main watch button and autoplay pick: the pinned link still wins, then the preferred tier, then the normal ranking (`bestSource`, with tests).
- The source sheet can be narrowed by quality with chips (كل الجودات / 4K / 1080p / 720p / 480p), and its counter follows the filter.
- A stream row now says when the addon advertises Arabic or dubbing ("عربي"، "مدبلج"، "متعدد اللغات"), read from the stream's own text with tests.
- Episodes whose addon sends an "S02E05" tag in the title instead of season/episode fields are labelled and ordered from that tag, so the next-episode button works for those series too.
- While a search runs, the line under it counts what has arrived ("نتائج حتى الآن: 12 من 3 إضافة…") instead of waiting for the slowest addon silently.
- A source sheet that came back empty now offers "أعد المحاولة" and fetches the streams again instead of leaving the user with a message only.
- The player overlay gained −10 ث / +10 ث buttons next to the speed chips, so seeking no longer depends on the double-tap gesture.
- A long press on an episode marks it watched (or clears the mark), kept in `WatchedEpisodesStore` separately from the real resume points, so the ✓ and the progress bar reflect it without polluting continue-watching. Tests cover the store.
- An end-to-end audit pass fixed five defects: switching titles no longer flashes the previous title's metadata and episodes, the resume label follows the episode that is actually selected, a link that just failed is not retried first during fail-over (it is now ranked with its track record), marking an episode watched clears its resume point instead of leaving it in continue-watching, and an empty source list under a quality filter names the filter instead of blaming a dead link.
- A slow or hung addon no longer holds a screen: each addon's streams call is capped at 15 seconds, each search at 12, and metadata is requested from all meta addons at once with a 10 second cap, taking the first answer in install order. One dead source can no longer stall the detail screen or the source sheet.
- Repeated requests are answered from a small cache inside `AddonRepository` (`TtlCache`, with tests): manifests for 10 minutes, first catalog pages for 3, metadata for 5 and stream lists for 60 seconds. Empty stream answers are never cached, so "أعد المحاولة" still asks again. Reopening a title, switching tabs or going back to an episode no longer repeats a round trip.
- Subtitle addons are asked in parallel with a 10 second cap each, the next episode's sources are prefetched in the background (which the same cache makes free), and every lazy row uses a stable key so lists scroll and update without re-composing their neighbours.
- A pass of ten smaller fixes and touches: the pinned source and the last-played link are stored per episode rather than per series, the repository cache is dropped when an addon is installed, removed or the home button is pressed, long series gain an episode search field, the player shows the remaining time next to the total, the debounced and pressed searches no longer run twice, the library and search screens show their counts, settings shows how many links it has a track record for, and the home refresh also reloads the free library.
- The rest of the source-unification plan landed: a title now has one identity (`core/MediaIdentity.kt`: IMDb, else TMDB, else folded title + year within one year of each other) used to de-duplicate search results and to make a favourite or a resume point survive the same film being opened from another catalog; `absoluteEpisodeIndex` and the "S02H" tag fallback cover differently numbered seasons; a per-addon quality preference is remembered when a link plays and gives that addon's tier a ranking bonus; the last-good link is stored by file fingerprint so a changed URL token still points at it; and addons that advertise `behaviorHints.configurable` gained an "إعداد" button that opens their own configure page.
- A film opened from two catalogs now gathers the sources of both: `TitleAliasStore` remembers every media id a title has appeared under (keyed by its identity) and the source sheet of a movie asks every known id, with tests. Series still ask their own episode ids, because another catalog's episode ids cannot be derived safely. The viewer decides: "دمج مصادر العنوان من كل الكتالوجات" in Settings turns the merging off.
- Episodes numbered absolutely are labelled S02E05-style when a TMDB key is set: `TmdbSeasons` reads the season lengths and `core/AbsoluteEpisodes.kt` (with tests) maps absolute 13 to S02E03. Without a key the "S02E05" title tag and the episodes' own order remain the fallback.
- "One page per title" is now the behaviour everywhere: the saved list, the resume list, search results and home shelves collapse a title that two catalogs number differently into a single entry, stored lists are migrated once on load, and the page of a film still gathers the sources of every id it was seen under. `FavoritesStore` and `WatchProgressStore` do that de-duplication in `load`, so an old library cleans itself up.
- The add-source sheet gained "لصق من الحافظة", so a manifest URL copied from an addon's configure page (opened by the "إعداد" button) installs in one tap.
- The source check now also detects addon updates: when a manifest advertises a newer version than the installed one, Settings marks it "تحديث X" with a "حدّث" button per addon and a "حدّث الكل (N)" button, which re-reads the manifest and refreshes the stored catalogs, types and configure flag.
- The search results grid and the catalog grid compute their column count from the available width (2–6 columns), so an iPad or a landscape window fills the screen instead of leaving a three-column strip.
- Settings can copy a backup to the clipboard and restore it on another phone: the saved list, the resume points, the hand-marked episodes and the installed addons travel as one JSON string (`Backup.kt`, `encodeBackup`/`decodeBackup`, with tests). A broken or foreign text is refused with a message instead of overwriting data.
- Player engine failover: when MPV fails on a link before the first frame, the same link is tried with the system player and the player says so ("تعذّر مع MPV — نجرّب مشغل النظام") before any source attempt is spent; the top bar names the engine in use (MPV / AVPlayer). The reverse direction is not needed, AVPlayer being the fallback.
- Arabic typography: a custom `Typography` re-cuts every Material style for a connected script — no letter spacing (which breaks the joins) and a 1.45× line height, so stacked Arabic lines breathe instead of colliding. The Settings screen groups its sources and app-data blocks in cards, and every section header now sits over a hairline separator with room above it instead of a cramped row. A bundled custom Arabic face (IBM Plex Sans Arabic) was prepared and then withdrawn: this build pipeline does not package compose resources for the static framework, so the font would have been missing at launch.
- Every episode row can be asked how many sources it has ("كم مصدرًا؟") without loading anything up front: the answer reuses the streams cache, shows "متوفر في N مصدر", and the episodes heading then reports the last episode known to be available.
- `docs/ADDON_ECOSYSTEM_REVIEW.md` compares the Stremio addon ecosystem (the official SDK example, awesome-stremio, stremio-public-domain and the official-sources availability addon) with what the app supports today: a per-feature verdict, a ranked backlog, the legal/security notes for each kind of source, and the first five items to build with their steps.
- `docs/ADVANCED_IDEAS_MAP.md` maps the larger remaining ideas into tiers with their dependencies, effort, risk and the signal that proves each one worked, plus the performance budget the app is held to.

## Known limitations
- Nuvio providers may `require` two bundled modules, which the runtime now provides through a shim shipped as `iosApp/Sources/nuvio-compat.js` and evaluated in its own guarded step (a failure there leaves `require` untouched): a static-HTML `cheerio` subset (tag/class/id/attribute selectors, `find`, `text`, `html`, `attr`, `each`, `map`, `first/last/eq`, `children`, `parent`, `next`, `hasClass`) and the `crypto-js` surface most scrapers use (`MD5`, `SHA256`, hex and base64 encodings). `tools/nuvio-compat.test.js` checks the same file with Node against known MD5/SHA-256 vectors and scraping patterns. Providers that need a real DOM or a full crypto library still fail, and only `fetch`-based providers were the previous limit.
- Nuvio providers need TMDB ids. Without a TMDB key, the raw item id is passed through, so many providers will find nothing for IMDb-based catalogs.
- If the mpv bridge is unavailable (for example a build without the Swift package), the AVPlayer fallback cannot decode MKV/AVI/WebM. ASS/SSA styling is only applied to embedded tracks, which libmpv draws itself; external subtitle files are rendered from parsed SRT/WebVTT cues, so their override tags and positioning are ignored. Profiles and account sync, intro/recap/outro skip services, Apple signing, and end-to-end physical-device testing remain to be implemented.

## Build
Requirements: macOS with Xcode 16+ and JDK 17+. `iosApp/CINEMAX.xcodeproj` is generated from `iosApp/project.yml` with XcodeGen and kept in the repository as generated output; its "Build CinemaxKit" run script links the static Kotlin framework with the committed Gradle wrapper, so the app can be built without a manual Gradle step (see `iosApp/README.md`). The iOS CI workflow builds the device and simulator frameworks, regenerates the project with XcodeGen, and packages unsigned Simulator and iPhone `.app` outputs. The iPhone output is not signed and is not directly installable or distributable.

## Optional signed iOS release

A manual workflow named **iOS signed release** is available under GitHub Actions. It archives the iPhone app and exports an App Store Connect IPA when the repository has these GitHub Actions secrets configured:

- `IOS_DISTRIBUTION_CERTIFICATE_BASE64`: base64-encoded Apple Distribution `.p12` certificate.
- `IOS_DISTRIBUTION_CERTIFICATE_PASSWORD`: password for that `.p12` file.
- `IOS_APP_STORE_PROFILE_BASE64`: base64-encoded App Store provisioning profile for `com.cinemax.app`.
- `IOS_TEAM_ID`: Apple Developer Team ID.

The certificate and provisioning profile must belong to the same Apple Developer team and match the app's bundle identifier. Add secrets in the repository's **Settings → Secrets and variables → Actions**, then run **Actions → iOS signed release → Run workflow**. Never commit signing certificates, provisioning profiles, passwords, or private keys to the repository. Without these owner-provided Apple signing assets, the workflow intentionally stops before signing.

## Compatibility and safety
Stremio addons are remote HTTP services; their responses are parsed as data and never evaluated as code. Nuvio providers are executable JavaScript: they run only after the user enables them, inside a JavaScriptCore context with no filesystem, keychain or native API access, HTTPS-only `fetch`, bounded timers and timeouts, and unsupported modules rejected. Their output is still parsed as data. Compatibility is provider-specific and must be tested. Use only content sources you are authorized to access. CINEMAX does not host media.
